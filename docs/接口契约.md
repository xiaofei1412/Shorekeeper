**公共接口契约 v0.4**

日期：2026-11-16。状态：设计基线，尚无服务。M01A只实现下述最小工程切片及所需schema，其余由M01B和对应模块实现；不要求先把全契约造完。不能把本文当已经运行的API。

当前模型仍待核验。v0.4只增加M01A最小服务切片，素材批次/审核与身份/事件/记忆语义不变；历史素材契约不迁移、不覆盖。

协调助手维护本文；模块AI提出变更请求后，相关字段、调用方和契约测试一起更新。兼容性新增字段可升次版本；删除字段、改变含义或授权规则需明确迁移。代码生成schema与本文不一致时先解决差异，不能维护两套相互矛盾的真相。

**通用约定。**

- 内部ID使用UUID4字符串；渠道外部ID作为不透明字符串保存，不解析成昵称或整数身份结论。
- 时间使用带时区的UTC ISO8601；界面按Asia/Shanghai展示。外部occurred_at和本机received_at分别记录，排序水位使用数据库分配的scope_seq，不依赖外部时钟。
- schema_version标记结构版本；所有业务操作携带request_id，长任务有job_id。日志只在必要时引用内容，默认记录ID、计数和错误。
- null、空列表与缺失的语义在对应schema中固定。模型产生的结构使用严格校验；不能用任意JSON透传到工具执行层。
- 失败返回error.code、可读message、request_id、retryable及必要details。不得在错误中泄露token、凭证、私人内容或未经授权的绝对路径。
- 通用错误码：INVALID_ARGUMENT、UNAUTHENTICATED、FORBIDDEN、NOT_FOUND、CONFLICT、BUDGET_EXCEEDED、BUSY、CANCELLED、DEPENDENCY_UNAVAILABLE、TIMEOUT、INTERNAL。TIMEOUT不自动意味着外部动作未发生。

**身份与作用域由核心生成。**

ActorContext是可信连接/平台信息经身份服务生成的内部对象，包含以下字段：

| 字段 | 含义 |
|---|---|
| person_id | 稳定人物ID，owner只有一个 |
| channel | desktop / qq / system |
| channel_account_id | 已验证连接所对应的平台用户ID；system可空 |
| conversation_id、scope_id | 当前会话与记忆作用域 |
| social_role | owner_rover / rover_friend；system为独立内部类型 |
| authenticated_owner | 是否已通过绑定或可信本地会话认定为漂泊者 |
| allowed_memory_scopes | 本轮允许检索的范围，由程序计算 |
| capabilities | 本入口明确允许的程序能力，由策略计算 |
| auth_revision | 身份/授权配置版本，变更后旧计划重新校验 |

客户端事件不允许直接设置authenticated_owner、allowed_memory_scopes、capabilities或auth_revision。QQ桥接使用经过平台连接验证的ID，不采信消息文字中的身份声明；system事件只能由已注册内部进程生成。模型输出、摘要、角色包与关系标签均不能修改这些字段。

作用域规则：

- character:public：已审核角色公开知识；不得混入私人资料。
- owner_private:<owner_id>：漂泊者私人记忆，只对显式允许的已绑定私聊/桌面入口可见。
- desktop:<profile_id>、dm:<channel>:<conversation_id>：各自会话历史。
- group:qq:<group_id>：该群历史；群里即使由漂泊者发问，也不自动获得owner_private。
- 明确分享时创建具有目标作用域和分享记录的新条目，不由模型把原private记录改成public。来源引用也不能让群用户反向读取私人原文。

绑定与授权是两种独立操作：把QQ绑定为漂泊者，不等于自动授予该入口所有桌面工具。权限由本地可信配置或明确批准授予。

**标准事件与媒体。**

InboundEvent包含event_id、schema_version、channel、platform_event_id、idempotency_key、conversation_id、actor来源信息、kind、occurred_at、received_at、parts、reply_to_event_id、metadata。核心接收后填入可信person_id、scope_id和scope_seq。

kind初期支持message、activity、reminder、tool_result和system_status。parts是有序内容数组：

- text：纯文本；不作为可执行HTML。
- image：asset_id、mime、宽高及必要来源信息。
- audio：asset_id、mime、时长；转写另存派生文本并保留来源。
- file：asset_id、mime、文件名和大小；原文件内容不直接塞进prompt。

附件通过媒体服务保存并计算hash，返回MediaRef：asset_id、sha256、scope_id、mime、size_bytes、relative_path、source_ref、derived_from、validity。远程URL只是临时来源；本地路径由媒体服务解析并验证在允许目录，不接受模型给出的任意路径当合法附件。对外API仅返回经过授权的资源ID或受控下载地址。

SourceRef包含source_kind（event/asset）、source_id、source_revision、scope_id和可选range。range使用明确单位：文本为Unicode码点的[start,end)区间，音频为毫秒区间，其他媒体可引用整个asset。来源范围必须可核对，派生链保留祖先引用，用于纠正、删除和防止再提取；字段未提供范围时按整个源对象处理。

入站幂等键由渠道加稳定平台消息标识构造；同一事件重发返回原event_id和seq，不重复排队。无消息的内部事件由调用方提供稳定幂等键。接收成功表示已经持久化或明确排队，不表示已经回复。消息被决定不回复时也保留disposition及原因类型。

生成、平台接收、播放和读取的状态分别记录。模型生成出的文本是generated；QQ确认接收为sent/accepted_by_platform，不代表对方已读；本地音频播放完成为played，不代表能证明人听见。失败、未发出和被取消的内容不能记录为完整已交流经历。

**RuntimeProfile是上下文预算的事实来源。**

由推理适配器提供，不由记忆模块猜测：

| 字段 | 含义 |
|---|---|
| profile_id、revision | 已验证配置标识；与ContextPlan绑定 |
| model_id、model_revision、model_sha256 | 唯一基座和实际权重 |
| mmproj_sha256 | 当前视觉组件；不可随意跨基座混用 |
| runtime_version、runtime_binary_sha256 | llama.cpp实际版本 |
| tokenizer_fingerprint、template_fingerprint | 实际计数和聊天格式依据 |
| effective_context_tokens | 单slot有效窗口，初始值见总体方案；不是模型原生最大窗口 |
| generation_limit_tokens、safety_margin_tokens | 本任务输出与安全预留 |
| enable_thinking、preserve_thinking | 实际生效的模板设置，日常均false |
| media_limits | 张数、尺寸、最大视觉token、支持的预处理与计数方式 |
| supports_tools、supports_json、supports_cancel | 经过M00验证的功能标志 |
| resource_profile | 文字或语音资源配置标识；不代表切换基座 |

measure_context(messages, tools, media, runtime_profile)返回：text_tokens、media_token_bound、template/tool计数是否已包含、input_token_bound、measurement_kind、profile_revision。不能重复计算已含在模板中的工具schema；也不能漏掉媒体。

measurement_kind至少区分exact_total与exact_text_plus_media_bound。普通文本tokenizer不等于图像计数。无法得到安全媒体上界时，明确拒绝该输入或走有界预处理，不能返回一个伪精确值。服务返回的usage用于校准和错误检测，不是超限发送后的补救。[llama.cpp计数与模板接口依据](https://github.com/ggml-org/llama.cpp/blob/master/tools/server/README.md)

**ContextPlan是一次生成的有界输入快照。**

build_context(scope_id, current_event_id, task_id?, runtime_profile)返回ContextPlan，包含plan_id、job_id、scope_id、current_event_id、persona_version、checkpoint_revision、memory_epoch、auth_revision、runtime_profile_revision、messages、selected_tools、media_refs、source_refs、budget和context_digest。

budget包含C、R、S、input_token_bound、soft_threshold、fits、measurement_kind及各部分占用。唯一硬准入是input_token_bound + R + S ≤ C；R改变时重新构建。软阈值与压后目标见总体方案，不能用另一个“硬阈值”覆盖这个公式。

messages使用当前模型支持的system/user/assistant/tool及媒体结构。可信system只来自程序和审核角色包；检索内容、原始聊天、网页、图片OCR和工具输出明确作为不可信数据呈现，不能转换成可覆盖系统或权限的指令。工具调用和对应结果必须成组保留，不能留下悬空消息。

生成前核心复核授权、删除epoch和引用有效性；运行时复核profile、模板与预算。版本变化则重建或返回CONFLICT，不能生成后再假装使用了新配置。删除/纠正与进行中的生成冲突时，取消相关旧任务并在投递前再核对epoch，过期结果不得送出。已经送达的信息无法通过取消撤回。

首版memory_epoch定义为数据库内全局单调递增整数，任何记忆删除、来源遮蔽或纠正都递增；一次ContextPlan即使引用多个scope也只核对同一epoch。各模块不能自行把它解释成仅当前scope版本。身份授权另由auth_revision管理。

generate(ContextPlan)产生有序流事件，带job_id、seq与scope_id：started、text_delta、tool_call、completed、cancelled、failed。completed包含可见回复、结构化工具调用、实际usage和结束原因；reasoning不作为普通可见内容、历史上下文或长期记忆持久化。工具规划需要的计划用应用任务状态表达。

cancel(job_id)是幂等请求。排队任务可以直接取消，执行中任务由适配器中止；中止确认前仍标cancelling。取消后不能把旧流片段追加到下一个job。usage中所有生成token，包括工具参数和启用时的reasoning，必须受R约束。

**单一调度器管理所有主模型任务。**

job.type包括reply、tool_plan、summarize、memory_extract和initiative；都调用同一主模型。交互优先于后台整理，平台回复有效期和公平性纳入调度，不能让群任务永久饥饿。每个scope串行推进会话状态，初期同一时刻仅一个主模型任务实际生成。

队列设全局和每scope上限，配置必须为有限正数；过载时显式BUSY、合并适合合并的普通群消息或延后后台任务，不丢弃已经接受的明确执行请求。没有承诺回复的普通群消息可以记录为观察事件。长期后台工作支持分段取消，不能一直占住交互。

job状态为queued→running→succeeded/failed/cancelled；运行中取消经cancelling。工具实际动作另有状态机，主模型job取消不等于外部动作被撤回。job_id和task_id分别表示一次推理与可跨多步的业务任务。

**记忆服务接口与持久化语义。**

| 接口 | 输入 → 输出 |
|---|---|
| append_event | 标准事件＋幂等键 → event_id、scope_seq、是否重复 |
| retrieve_memory | 查询、可信allowed_scopes、主体/时间条件、token预算 → 有界MemoryItem和SourceRef |
| build_context | 当前事件、scope、任务与RuntimeProfile → ContextPlan或明确失败 |
| compact_scope | scope、cutoff_seq、expected_checkpoint_revision、memory_epoch → 新checkpoint或失败 |
| propose_memory | 已存在的来源事件ID → 候选条目；不得直接改身份/权限 |
| correct_memory | 条目ID、可信操作者、修订内容、expected_revision → 新版本及旧派生失效 |
| delete_memory | 目标ID、删除范围、可信操作者 → tombstone、epoch、受影响派生与备份状态 |
| rebuild_scope | 当前有效原始事件、角色/摘要版本 → 新摘要与索引，保留来源 |

MemoryItem至少有memory_id、subject_person_ids、kind、content、scope_id、source_event_ids或asset_refs、asserted_by、valid_from/to、status、revision、supersedes。status区分candidate、active、superseded、deleted；kind区分canon、reported_fact、shared_event、open_task、uncertain。

模型输出只能产生候选。程序检查来源存在、范围、主体、删除状态与结构；存在引用并不证明语义正确，高影响、角色原设和冲突内容需规则或人工复核。错误的源材料不能因为经过摘要就变成可信设定。

Checkpoint至少包括scope_id、revision、source_cutoff_seq、memory_epoch、summary、open_task_ids、unresolved、source_refs、persona_version、summary_schema_version、summarizer_model_hash、created_at。自然语言摘要不能保存工具授权或替代结构化任务状态。

compact_scope的约束：

1. 读取稳定快照和旧版本，按有界片段生成；每scope最多一个压缩在进行。
2. 校验模型JSON、引用、作用域、删除状态和摘要长度。
3. 短事务重新核对expected_revision及epoch，成功才原子写入checkpoint并推进cutoff。
4. 新消息seq大于cutoff作为尾部保留；过期结果失败，不覆盖新版本。
5. 超时、取消、崩溃或无效JSON保留旧checkpoint和原始事件。有限重试后确定性裁剪，仍不能满足预算则拒绝本轮生成。

不要无限“摘要再摘要”丢失证据；纠正、删除或版本不兼容时，从有效原始事件分块重建。清理上下文和可重建缓存不等于删除原始记录。

删除不能只移除memory_id：delete_memory必须解析来源及已知派生/重复引用，持久记录受影响event/asset/range的墓碑或遮蔽规则，相关原件按删除范围移除、遮蔽或禁止再利用。原始事件若保留，append后的直接回放、retrieve、build_context、propose_memory和rebuild也必须统一应用源证据遮蔽规则；新memory_id不能绕过。规则只保存必要ID、范围和状态，不另复制被删原文。纠正建立带时间与优先级的覆盖记录，保留已发生历史与当前事实的区别，防止旧原文再提取覆盖纠正。

删除同时使相关摘要、检索索引、附件派生、进行中计划与缓存失效；恢复备份先应用最新删除/纠正覆盖记录，再开放检索。对已识别来源与派生保证不再使用，不声称自动识别所有未知语义重复；新的明确输入是新事件，是否重新记忆由用户意图决定。也不承诺对基座预训练知识进行模型遗忘。

**工具与真实任务使用独立状态机。**

ToolDescriptor包含name、version、description、args_schema、result_schema、required_capabilities、side_effect_type和默认超时。展示给模型的只是本轮相关、已允许的工具schema；模型生成工具调用仍必须经过执行前权限复核。

ToolCall由模型提出name和arguments；核心附加task_id、call_id、ActorContext、scope_id和幂等键。模型不能通过arguments传入或覆盖owner、capabilities、审批状态和沙箱范围。

authorize(call, actor_context, policy_revision)返回allowed / confirmation_required / denied，并记录可解释的规则码。路径解析、应用范围、外部目标和参数检查在程序层完成；名称相同的工具在不同入口可有不同能力范围。

需要确认的动作生成ActionProposal：action_id、canonical_args、args_hash、target_summary、policy_revision、expires_at、requester。可信本地界面批准绑定该hash、策略和有效期；改变参数、过期或策略变化后重新判定。对话中一句“我同意”不自动构成任意动作审批。

已允许的动作由prepared进入executing；需批准的动作先进入awaiting_confirmation，批准后才进入executing，拒绝则终止于denied。executing最终进入succeeded、failed或unknown；未开始的动作可终止于cancelled。记录必须先于实际副作用持久化。超时、断线或崩溃后无法判断结果时进入unknown，核实目标状态后再决定，不能盲目重发。read-only动作也记录结果；取消不能假称回滚已经发生的副作用。

ToolResult包括call_id、execution_state、result_summary、evidence_refs、error、output_artifact_refs及实际持续时间。提示只接收有界摘要和必要片段，完整stdout/网页/文件留在授权本地附件。每一步重新预算，并有max_steps、总时长和单工具超时，达到限制就终止或明确等待继续。

业务TaskState保存目标、当前步骤、动作ID、输入/输出引用、状态和未完事项，拥有revision与幂等信息。摘要只引用task_id；动作批准、真实文件路径/草稿hash和执行证据不由摘要重新发明。

**语音、桌面与QQ共享一份回复身份。**

所有出站内容携带response_id、job_id、scope_id、reply_to_event_id和delivery_id。文字片段和语音片段以segment_id对应，不因两个入口各自调用模型而生成两个人格版本。

SpeechRequest包含response_id、segment_id、text、voice_profile_version、style参数和cancel_group_id；风格参数有白名单，不接受任意音频路径。SpeechResult提供audio_asset_id、格式、时长和生成状态。PlaybackEvent记录queued、playing、played、interrupted及已播范围。打断同一cancel_group的未播片段，同时终止相关生成；保留已发文字与实际播放状态。

QQOutbound使用稳定delivery_id、目标会话、reply_to平台引用、parts及deadline。适配器返回accepted_by_platform、failed、expired或unknown；unknown先核对幂等与平台情况，不盲目重复发送。收到过期媒体URL时重新获取或明确失败，不能记成已看见原图。QQ凭证只由连接配置访问，不进入模型消息。

**素材、角色包与训练产物清单。**

AssetManifest按来源分片为JSONL，每条含：asset_id、kind、relative_path、sha256、source、source_version、collected_at、source_group_id、labels、review_status、rights。rights分别记录local_research、training、redistribution、commercial_use的allowed/restricted/unknown以及依据和核对时间；默认unknown，不自动从软件许可继承角色/声音许可。

DerivedSample记录sample_id、source_asset_ids、源文本范围或音频时间段、处理脚本版本/参数、人工复核、dataset_version、split。来源分组后划分数据，测试样本不能被后续生成步骤回灌训练集；测试集变化应另升版本。

新增资料统一放local/assets/batches/<batch_id>/，不改变M02A/B旧根目录文件集合。BatchManifest即batch.json，至少记录schema_version、batch_id、kind、日期/时区、purpose、state、parent_refs、实际数据文件入口和counts；可补来源版本、工具/处理版本、缺口及dataset_release。只有实际存在的原件进入该批manifest；人工反馈批次可以raw_files=0并引用已有asset_id/hash，不重复计算为新录音。

人工反馈接收记录保存feedback_id、来源/日期精度、用户原话、实际适用范围、原件ID/hash、文本补充及未确认项。总体质量反馈不自动填充所有逐项声学维度，也不延伸至新素材。用户提供全文与时间对齐是两件事，未给出的时间继续null。首次记录先保留原话，后续导入再产生明确的审核/转写后继，不回写旧草稿。

新批审核必须能定位冻结的目标记录文件及行hash；追加base_record_ref指向具体输入路径。supersedes_review_id只能引用同target_kind/target_id、同原记录hash的已存在审核；禁止环和未知前驱，多个未解决后继视作冲突，不能按时间戳盲取最新。转写补充以新transcript_id及supersedes_transcript_id保留旧版本。旧校验器只负责旧快照，不据此假称支持新批次；实现所需最小引用检查，不先建通用工作流平台。

数据集发布清单显式列入批次/记录/有效审核版本、用途、排除项与分组划分；不采用“扫描所有目录即全部训练”的方式。跨模态/跨批的原始来源组保持关联；20个既有test_only题及其明显改写不进入训练。

ReviewOverlay用于审核冻结资料，不直接覆盖M02A索引或manifest。每条包含review_id、schema_version、target_kind、target_id、base_record_sha256、asset_sha256（涉及原件时）、reviewer_kind、review_method、reviewed_at、decision、checks、corrections、added_source_refs、notes、supersedes_review_id。target_kind支持evidence、audio_candidate、scene、art_reference；base_record_sha256为原始JSONL目标行的UTF8字节SHA256，排除行尾CR/LF。审核的是原始记录与指定文件的固定版本，hash变化必须重核，不能套用旧结论。

reviewer_kind为human、text_or_image_model、audio_capable_model或code_only；review_method记录实际方法及可复核依据，不能只自报能力。decision分accept_reference、needs_review、exclude。accept_reference只表示经声明方式审核后可用于对应参考用途，不代表训练集、使用许可或全场景均已通过。新的修订另建review_id并引用被取代记录，保留历史；同目标冲突结论在解决前不得自动入库。

音频checks至少有direct_listening_performed、language、speaker_assessment、bgm、overlap、truncation、distortion、transcript_status。未直接听到的维度保留unknown/unreviewed，不能因code_only结构检测、ASR或启动了播放器而填已听审。audio_capable_model须确实具备本次音频输入/理解能力并留下审核方法；无法听音的执行者交付待人工包，不能自行升为声线或TTS合格候选。rights仍按原资产独立追踪。

音频目标的程序校验约束：direct_listening_performed=false时，decision只能为needs_review或exclude，不得为accept_reference。direct_listening_performed=true时，reviewer_kind只能为human或audio_capable_model，且必须提供实际审核方法；技术检查结果单独写checks，不提升听感准入。

Transcript记录transcript_id、asset_id、source_sha256、language、segments及status。segment含segment_id、start_s、end_s、text、status、source_refs；时间以原文件秒计，已对齐段满足0≤start_s<end_s≤原音频时长。未确定边界使用null并标alignment_pending，不伪造精确时间。status区分draft_asr、draft_source_text、reviewed_by_listener；ASR和网页同名条目不能自动升级为听审文本。剪辑或重采样产物保留原文件范围、转换参数与新hash，不改原件。

角色规格草案必须区分canon_reference、project_directive和working_interpretation，逐条引用证据/审核ID并保留不确定性。working_interpretation不能伪装为游戏原话；社区转录不能仅因claim_type=canon_fact就成为硬设定。source_group_id只是防泄漏分组标识，名字中的1.3等字样不构成实际来源版本证据。

PersonaBundle记录persona_version、identity/relationship规则、风格原则、正反例、知识索引版本、voice/avatar引用及来源说明。动态私人记忆不嵌入角色包，也不自动成为训练材料。

ModelReleaseManifest记录base_revision、dataset_version、training_code_commit、tokenizer/template、超参数、LoRA/合并权重hash、量化器版本与配方、校准数据版本、GGUF/mmproj hash、所需RuntimeProfile、评测报告、许可记录和回退版本。新模型正式启用前先验证兼容性和回归，不覆盖唯一旧可用版本。

**工作台最小API边界。**

M01A当前只实现health、status、speech不可用切片；其余保持设计状态，后续M01B/对应模块再实现。路径和语义以此契约为准，变更由协调助手维护。

M01A健康与状态：GET /api/v1/health只返回进程健康（status=ok、scope=process_only），可无令牌但只监听loopback；GET /api/v1/status需要本机会话令牌，返回product_ready=false，inference/tts/memory/qq等组件均not_configured。健康不意味着模型、身份绑定或业务就绪。令牌只用于本地会话保护，不代替后续ActorContext服务。

M01A POST /api/v1/speech也需要令牌。入站最小字段为text（去除空白后1–1000字符）、voice_profile_version（非空）；response_id、segment_id、cancel_group_id可选UUID4，由程序规范化。当前不接受任意文件路径或额外字段，不实现style/stream。未授权401；非法输入422并用通用INVALID_ARGUMENT错误；合法输入503及DEPENDENCY_UNAVAILABLE，不生成音频、假job或假成功。SpeechResult仅定义后续真实合成需要的状态、audio_asset_id/格式/时长与错误字段，M01A不填造产物。

M05A可先做独立worker与试听CLI，不要求该HTTP入口立刻变可用；只有后续实际集成并验证后，status中的TTS才改变。当前服务与语音环境分离，核心依赖锁不包含整个TTS推理栈。

| API | 责任与限制 |
|---|---|
| GET /api/v1/health、/status | 健康、版本、队列与资源；不泄露凭证 |
| POST /api/v1/speech | M01A校验后明确返回未接入；后续真实TTS模块接入再启用，不允许任意本地路径 |
| POST /api/v1/events | 授权入口提交事件，返回接受/去重/拒绝状态，不阻塞到回复完成 |
| GET /api/v1/events | 按授权scope分页；不允许客户端任意扩大scope |
| WS /api/v1/stream | 带游标和序号的状态/回复流；鉴权与来源检查，断线后可去重恢复 |
| POST /api/v1/jobs/{id}/cancel | 幂等取消，显示请求与最终取消的区别 |
| GET /api/v1/memories | 作用域、主体、时间查询，返回来源与版本 |
| PATCH/DELETE /api/v1/memories/{id} | 可信操作者纠正/遗忘，返回派生失效和删除状态 |
| GET /api/v1/context | 使用量、预留、摘要覆盖与版本；完整内容仍需对应范围授权 |
| POST /api/v1/bindings | 本地可信操作绑定渠道身份，与工具授权分开 |
| POST /api/v1/actions/{id}/decision | 批准/拒绝具体hash与有效期的动作 |
| GET/PATCH /api/v1/settings | 版本化配置；乐观并发检查，不把凭证原文回显 |

核心、模型和界面仅loopback并不等于自动可信，仍需应用会话凭证与WebSocket来源检查。前端不能绕过后端直接控制推理端口或shell；外部网页内容不获得本地应用权限。

**跨模块必须保留的契约验收。**

- 同一平台消息重发不重复排队；未知发送结果不重复产生副作用。
- 昵称、群图片指令和摘要不能改变漂泊者身份、记忆范围或工具权限。
- 漂泊者在群内发问也不能召回owner_private；两字中文名字可正确检索。
- 连续回放多倍本地窗口历史仍无超预算请求；R改变后预算跟随变化。
- 计数包括模板、schema、图片及工具结果；计数不确定时保守拒绝或限额。
- 压缩时新增消息、取消、崩溃、纠正或删除均不丢尾部、不提交过期摘要。
- 删除后缓存与派生失效，原始来源保留时也不能经提取/重建生成新ID复活；旧备份恢复先应用墓碑/覆盖记录，生成中的旧结果不再投递。
- 语音打断、未送达文字和失败工具不会记为完整已发生事件。
- 同时多个入口不会串scope；流片段与取消均以job_id隔离。
- 模型升级后重新验证模板、token与媒体计数；历史thinking不持续累积。

这些是功能与边界测试，不要求为文档本身建立测试框架。模块实现后的证据记入对应任务卡，集成时验证真实链路而不是仅验证mock返回值。
