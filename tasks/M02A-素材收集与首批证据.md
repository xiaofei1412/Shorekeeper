**M02A：素材收集与首批可追溯证据**

负责人：原M02A模块AI；协调助手负责本轮验收记录。状态：完成——首轮采集与溯源验收通过（2026-11-16）；音轨实听、游戏路由/分支与训练数据准入移交M02B，不标全量素材完成。

目标：取得一批有出处、可复核、可供后续人格和语音工作的资料；同时明确哪些只找到入口、哪些已下载、哪些已复核。首轮做有限范围和质量样本，不要求收集所有版本或立刻产出可训练全集。

**首轮范围与优先级。**

以简体中文和官方中文原声为主，覆盖角色档案/语音菜单、1.3第一章第八幕和《回响》。剧情中其他人物的前后回应同样是上下文，不能只摘守岸人的名句。其他版本、歌曲与同人素材先列候选，不扩展首轮边界。

1. 复核起步清单的10个来源，保存发布者、语言、版本、可访问状态、页面/资源定位和实际取得情况。官方发布、平台编辑、社区整理、玩家解释分别标签。
2. 整理20–30条角色事实或表达证据：每条有出处、原文定位、说话者、对象、情境和复核状态。官方原话、事实描述、社区解释与项目自己的“用户=漂泊者”设定分开，不能相互冒充。
3. 定位3段连续对白场景，记录起止、轮次、人物和漂泊者分支；保留可回到原件的context_ref。公开网页先收索引与必要短样，完整场景优先使用合法提供的导出或本地导入，不为凑数量整站复制长篇剧情。
4. 登记10–15条中文原声音频候选，给出语音标题/页面/时间段、语言、角色、情境及混音状态。通过正常方式能取得时，再采集3–5个可试听的短样；无法播放/下载就登记缺口，不把候选算已取得。
5. 登记5–8项美术参考，优先官方角色图、表情、服装及黑海岸场景，能正常获取的原件保存并算hash。多个切图不得虚增独立来源数；参考图不标成可直接发行的Live2D模型。
6. 本地游戏如已安装，先通过启动器/安装记录定位，再仅盘点相关目录；未知路径不能靠遍历所有磁盘扩大工作。没有可确认安装位置时，将本地来源保留为缺口，继续公开来源部分。

以上数量是起步目标而非造数配额。缺少可靠来源时交付真实结果和差额；不因为凑不够样本而引入同人台词、生成语音或不明转载。首轮原始下载预算2GiB，优先少量代表性素材，不下载整包游戏资源或整套无关视频；需要更大范围时在交接中说明来源与必要性。

**采集与质量规则。**

- 网页记录稳定URL、发布者、来源版本/日期和采集时间；正常可下载的素材保存原件。访问受限时可用正常浏览器查看，记录状态，不伪造正文、音频或来源；不要运行未知来源的下载器或解包器。
- 本地盘点记录客户端/补丁版本、文本与实际安装语音语言、容器/索引文件的类型、尺寸及修改时间；先观察格式，再确定可信导出方式。这里只盘点，不修改游戏、不开展解密或访问控制绕过；若需新的专用导出工具，记录实际格式和下一步需求。
- 仅对真正采集的文件或实际使用的容器计算SHA256，不先给整个安装目录算hash。游戏正在更新时不把变动中的内容当固定版本。
- 文字保留原说话人、对象、上下文与原占位符；校正另存，不改原件。男/女漂泊者分支分开，未知则标unknown。页面重复不自动算独立证据。
- 音频先直接试听再评价语言、说话人、音乐、重叠、截断与失真。未听写unreviewed；去噪/分离后另记derived，不将分离音频称为原始清洁录音。不要仅靠ASR结果批准转写与声线。
- 战斗短句、剧情对白、角色档案语音和PV演出分别标签。不得把AI翻唱、TTS、RVC、同人配音或演员其他作品归为游戏原声。
- 美术标注形象/服装版本、表情、视角和来源。只做参考与原件整理，不制作桌宠或训练视觉模型。
- 研究、训练、分发和商用的使用条件分别记录，未知保持unknown；不为了采集先替全部素材作统一授权结论，也不向外发布原件。

**输出格式保持模型中立。**

AssetManifest使用公共契约要求的asset_id、kind、relative_path、sha256、source、source_version、collected_at、source_group_id、labels、review_status、rights。只为真实取得的文件建资产记录；未取得候选留在索引表。

证据条目建议包含evidence_id、claim_type、content或必要短引用、source_ref、speaker、addressee、scene_id、rover_branch、context_ref、review_status。claim_type区分canon_fact、character_expression、community_interpretation和project_directive；标签不是新的公共API。不要提前转成Qwen4的messages模板或计算模型token。

音频候选包含source_ref、语音标题/时间定位、zh-CN等实际语言、角色、场景、acquired状态、listened状态、noise/overlap/truncation说明和asset_id（取得后才有）。美术索引同样区分候选与已保存文件。相关文本、音频、截图共享source_group_id，方便后续按来源分组划分，首轮不做最终训练集切分。

**验收。**

| 检查 | 通过依据 |
|---|---|
| 来源真实性 | 发布者、官方/社区属性与实际访问状态可复核；不把占位仓库或社区解释当官方素材 |
| 原件与清单 | 所有已取得文件hash匹配，路径存在，来源定位完整；候选不伪装为原件 |
| 文本情境 | 抽查至少10条证据和3段场景定位，能找到原文、人物与前后关系；无分支拼接 |
| 中文原声 | 候选与实得短样分别计数；短样提供可直接试听的绝对路径并记录质量；没有清洁音源也如实交代 |
| 美术 | 参考用途、版本与出处清楚；不存在虚构的可分发/可驱动形象 |
| 数据用途 | 私人对话未混入；原始资料、解释与项目设定分开；无模型模板绑定 |

访问限制、本地路径未知或某类素材不足，只阻塞该部分，不要求停止整个任务。核心通过条件是来源可靠、实际状态和可追溯样本；数量不足、未试听或下载失败在任务状态中明确列出，不能宣称“全套素材已收集”。

交接在本卡内填写：负责人和基线；实际文件数/字节数与来源覆盖；证据/场景/候选/短样的分别计数；校验与抽查结果；声音与图片可检查路径；未取得内容及原因；本地资源盘点结果；M02B下一步建议。协调助手据此评估后再派发清洗、标注或资源导出任务。
