**实现与验收。**

1. 先核对桌面配置和后端端口一致，启动本次所属后端及工作台。允许窗口在TTS加载时显示现有状态。进程参数由程序固定构造，向工作台传递私有配置位置，避免记录令牌值。确认从包含中文或空格的路径启动正常。
2. 后端端口已占用时给出清楚提示，继续使用双终端的独立连接办法。连续启动两次时仅一次能取得端口并加载模型。端口检查以真实绑定结果为准，不能接管已有服务或按进程名结束进程。
3. 窗口正常关闭、启动中失败及启动器中断均应清理本次持有的进程树。优先使用已有的安全退出办法，留有限等待时间后再收尾；验证Windows虚拟环境启动器的实际子进程也已退出。关闭手动启动的旧工作台仍保持其现有行为。
4. 至少实际双击入口等效启动一次，验证加载中至就绪、新文字合成播放及关闭后端口释放。测试已有监听、重复启动、缺失构建和启动失败。真实GPU链路与受控故障验证分别记录，证据放 local/reports/M04B/<run_id>/。

**交付记录（2026-11-22）**

- 新入口为根目录的 `启动工作台.cmd`。启动器位于 `tools/desktop_launcher/launch.py`，使用桌面配置中的端口与既有会话令牌文件，调用正式 `python -m shorekeeper` 和当前工作树已构建的 Electron。支持通过绝对路径复用私有桌面配置、TTS 配置及核心解释器。首次按[工作台说明](../apps/desktop/README.md)准备，日常启动时检查依赖和构建文件。
- 使用 M05B1 的排他监听结果判定启动权，再打开窗口。复用 Windows Job 收纳后端、Electron 及其后代。关闭或中断时向本次后端组发送 Ctrl+Break，最多等待 8 秒，然后回收该 Job 的剩余进程。私有日志写入当前源码目录的 `local/runtime/desktop-launcher/`，测试检查实际会话令牌值未出现在本轮日志和证据中。[Windows 控制台事件](https://learn.microsoft.com/en-us/windows/console/generateconsolectrlevent) · [Windows 嵌套 Job](https://learn.microsoft.com/windows/win32/procthread/nested-jobs)
- 实测 Python 3.12.16、uv 0.13.8、Uvicorn 0.54.0、Node 24.14.0、npm 11.14.1、Electron 45.4.1。根目录运行 `uv sync --locked --group test`、`python -B -m pytest -q`，71 项通过，保留一条 Starlette TestClient 弃用提示。`apps/desktop` 运行 `npm.cmd ci`、`npx.cmd --no install-electron`、`npm.cmd run build`、`npm.cmd run typecheck`、`npm.cmd test`，均通过，桌面 5 项测试通过。
- 真实链路使用任务工作树的 `启动工作台.cmd`，通过 Windows `cmd /d /c call` 等效启动。主配置与令牌复用既有文件，TTS 配置仅为验收复制并指定本轮输出与日志目录。实际界面和状态接口均观察到「加载中」到「已就绪」。RTX 5080 Laptop GPU 上合成一条新文本，生成 13.76 秒、24 kHz 单声道 WAV。原生播放器进度前进至末尾并报告「播放已结束」。加载期间再次运行入口，第二次由真实端口绑定拒绝，首个窗口继续就绪，全程仅创建一份语音 worker 日志。正常关闭后观测到 Uvicorn 完成应用关闭、13 个记录到的进程全部退出，8765 可再次排他绑定。
